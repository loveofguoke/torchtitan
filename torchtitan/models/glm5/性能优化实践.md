编排分开，避免一个尚未验证的性能想法影响模型正确性。

## 已确认实现

`ops/triton.py` 提供两个显式 override：

```bash
--override.imports \
torchtitan.models.glm5.ops.triton.triton_dsa_indexer,torchtitan.models.glm5.ops.triton.triton_sparse_mla
```

- Lightning Indexer：Triton 融合 score 计算，完整 key 范围上做 exact top-k；
- SparseMLA：只访问 top-k compressed KV，具有 Triton forward 和 backward；
- TorchTitanTurbo：用 Triton-Ascend 注册同一数学实现，并另有 Ascend native sparse
  attention 路径。

“已确认”表示设计和组件归属已经明确，并不等于所有 GPU/NPU shape 与拓扑已经实机
验收。实机仍必须完成 operator、精度、分布式和 profiler gate。

## 优化原型地图

| 优化维度 | 原型 | 来自的工程思想 | GLM-5 落点 |
| --- | --- | --- | --- |
| 计算 | Triton residual RMSNorm | TorchTitan/Megatron 融合 transformer primitive | block residual/norm |
| 通信 | chunked overlap | TorchTitan graph EP、Megatron MoE overlap | EP dispatch/compute/combine |
| 通信/内存 | contiguous bucket planner | Megatron DDP/distributed optimizer | grad reduce/param gather |
| 通信 | DTensor redistribution audit | TorchTitan SPMD placement | 多轴 Partial -> Replicate |
| 通信/内存 | FSDP layer grouping | TorchTitan FSDP2、Megatron/DeepSpeed bucket | 相邻 block 的 shard 粒度 |
| 流水 | measured stage partition | Megatron schedule、DeepSpeed balanced partition | PP stage 和 microbatch bubble |
| MoE | expert placement what-if | Megatron/DeepSpeed token dispatch | EP rank payload 不均衡 |
| 内存 | stream-local workspace | TorchTitan fused collective-linear | index/SparseMLA scratch |
| 计算/内存 | selective recompute planner | TorchTitan AC、Megatron recompute | block activation 和 top-k |

## 面试时需要讲清楚的统一方法

### 计算优化

先用 profiler 找到 kernel launch、HBM bandwidth 或 GEMM 利用率瓶颈，再选择 fusion、
Triton kernel、grouped GEMM 或低精度 GEMM。融合的本质是减少中间张量读写和 launch，
但会增加寄存器压力、编译 shape 数和 backward 复杂度。

### 通信优化

通信优化不是让 collective API 自身“更快”，而是缩短 critical path 上暴露的通信：

```text
同步: dispatch -> wait -> expert GEMM -> combine -> wait
重叠: dispatch(i+1) 与 GEMM(i) 重叠，combine(i-1) 延后到 consumer 前等待
```

关键问题是 chunk、双缓冲、stream/event、autograd、动态 token 数和 rank 一致的发起
顺序。NCCL/HCCL 不应该由 Triton 替代；Triton 负责通信前后的 pack/unpack/reduce。

### 内存优化

分别看 active、reserved、allocation event、fragmentation 和峰值生命周期。workspace
复用减少 allocator 压力但可能长期占住内存；chunking 降低峰值但增加 launch；paged
cache 提高推理 KV 利用率但引入 block table、refcount 和 copy-on-write。

### 重计算与缓存

activation checkpoint 用更多 backward compute 换 saved activation；offload 用传输换
device memory；cache 用更多常驻内存换重复计算。GLM 的 top-k 是离散控制流，重算
可能翻转边界，因此必须保存或证明 deterministic。

## 完整优化闭环

```text
固定模型/ckpt/token plan/topology/precision
  -> profiler 定位瓶颈
  -> 单变量候选实现
  -> operator 数学和 backward
  -> 端到端 loss/grad-norm
  -> 目标分布式拓扑和 graph
  -> profiler 解释机制
  -> profiler-off 重复吞吐和峰值内存
```

测试、采集和 HTML 报告属于 torchtitan-test；NPU 注册、HCCL/CANN、Triton-Ascend
或 Ascend native operator 属于 TorchTitanTurbo。TorchTitan 的 GLM 模型不导入后二者。
