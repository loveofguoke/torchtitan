## 一、背景与目标

### 1.1 项目背景

GLM-5.2 模型需要在国产昇腾 NPU 平台上完成训练适配与优化，主要技术栈如下：

- **训练框架**：TorchTitan（PyTorch 原生分布式训练参考实现）
- **硬件平台**：昇腾 A3 训练集群
- **软件栈**：CANN、torch_npu、PyTorch、TorchTitan
- **参照基线**：GPU 侧 TorchTitan 运行 GLM-5.2 的训练结果

### 1.2 核心目标

| 序号 | 目标 | 验收标准 | 责任人 | 当前状态 |
| --- | --- | --- | --- | --- |
| G1 | 跑通分布式训练流程 | FSDP + TP 多卡训练小时级稳定不崩 | 叶瑶波 / 黄怡淞 | 未验收 |
| G2 | 精度与 GPU 对齐 | 分布式泛化验证精度一致，GPU/NPU loss 误差满足已冻结的自洽标准 | 叶瑶波 / 黄怡淞 | 未验收 |
| G3 | 性能优化 | 8 卡减层 A3 分布式端到端训练性能达到 A100 的 1.1 倍 | 黄怡淞 | 未验收 |
| G4 | 分布式入图 | 分布式 graph mode 稳定运行，精度满足自洽标准；相对 A100 的性能阈值尚未冻结 | 黄怡淞 | 未验收 |

### 1.3 验收口径约束

- G2 所称“自洽标准”必须在阶段一 GPU 基线完成时冻结，至少包含 logits、loss、
  梯度和多步训练轨迹的比较对象、统计方法及容差。
- G3 的“1.1 倍 A100”必须使用相同模型配置、全局 batch size、序列长度、训练精度、
  并行语义和有效 token 吞吐口径。
- G4 的性能百分比当前没有确定值。在阶段四开始前必须完成指标评审并记录到本文档，
  未冻结前不作为可验收目标。
- 第 4 周的里程碑是阶段一基线完成，不代表总体 G1 已验收。总体 G1 需等待
  第 11 至 12 周的 FSDP + TP 多卡小时级稳定性证据。

## 六、精度与性能证据索引

### 6.1 精度报告最低字段

- GPU/NPU 硬件和卡数；
- CANN、torch_npu、PyTorch、TorchTitan 版本及提交；
- 模型配置、权重来源和 state-dict 转换方式；
- 数据样本、tokenizer、随机种子、训练步数；
- FP32/BF16/其他混合精度设置；
- logits、loss、代表性梯度及多步 loss 轨迹；
- 绝对误差、相对误差、容差及是否通过；
- 失败时的首个偏差层或算子。

### 6.2 性能报告最低字段

- A3/A100 具体型号、卡数和拓扑；
- 软件版本、并行策略和 graph/eager 模式；
- 层数、hidden size、专家数、序列长度和精度；
- micro batch、global batch、gradient accumulation；
- activation checkpoint、重计算和 checkpoint 配置；
- warmup 步数、测量步数和稳定区间；
- 每步耗时、有效 tokens/s、MFU、峰值内存；
- 计算、通信、空闲时间占比和 profiler trace 链接。
